# grapesjs-forms — устройство

## Идея

Форма — это **данные** (схема), а не дизайн. Схема живёт в хранилище форм (REST / IndexedDB / память),
редактируется в отдельном редакторе (модальное окно) и **собирается** в компонент GrapesJS из обычных
HTML-элементов со стабильными классами. Поэтому:

- форма выглядит как сайт: её стилизует CSS проекта (Style Manager), классы общие для всех форм;
- изменение схемы пересобирает все вставки формы в открытом проекте, свои классы/атрибуты `<form>` остаются;
- сервер проверяет заявку по той же схеме (`validateSubmission`), без DOM.

SurveyJS рассматривался как основа: раннер (survey-core, MIT) рисует свою разметку и темы — это
противоречит требованию «дизайн из страниц», а визуальный Creator — коммерческий. Поэтому своя
простая схема + импорт/экспорт SurveyJS JSON для того, что является обычной формой.

## Модули

| файл | что делает |
|---|---|
| `schema.ts` | типы полей, `normalizeForm/Field/Options/Settings`, `cleanAttrs` (без `on*`, `javascript:`, служебных имён), `validateSubmission` (коды как в 422) |
| `placeholders.ts` | `{{…}}`: `resolveBuild` (form.*, page.* — при сборке), список для подсказок |
| `build.ts` | схема → дерево `El` → HTML (`formHtml`) или компоненты; `formAttrs` (action, тексты, коды ошибок, версия, страница) |
| `runtime/script.ts` | поведение формы на сайте. **Самодостаточная функция**: GrapesJS копирует её текст в `getJs()` (`script` + `script-props`), поэтому без импортов и внешних переменных. Тест `runtime.test.ts` исполняет её из исходного текста, `export.test.ts` — экспорт целиком |
| `runtime/index.ts` | `enhanceForms()` для HTML без GrapesJS; отдельная сборка `dist/runtime(.iife).js` |
| `editor/FormComponents.ts` | типы `gjsf-form` (`formId`, трейты, скрипт) и `gjsf-part` (части: стилизуются, но не двигаются/не удаляются); пересборка вне undo; защита холста от реальной отправки; служебное правило `.gjsf-hp` |
| `store/*` | `FormStore`: `MemoryFormStore` (проверяет заявки как сервер), `IndexedDbFormStore` (поверх Memory, запись по ключам `form:` / `submission:`), `RestFormStore` (openapi.yaml, snake_case, If-Match, multipart для файлов) |
| `surveyjs.ts` | `fromSurveyJs` / `toSurveyJs` |
| `ui/FormEditor.ts` | модальный редактор: список форм; вкладки Поля / Настройки / Просмотр / Заявки / JSON |
| `plugin.ts` | сборка всего: кэш форм, отложенная запись с версиями, блоки, команды, API `editor.Forms`, связь с grapesjs-pages, контракт плагинов |

## Потоки

**Правка.** UI меняет свою копию формы → `change(form)` → кэш обновляется сразу (имя в блоках/трейтах),
запись в хранилище через `autosaveDelay` с `If-Match` = последняя сохранённая версия. 412 → форма
перечитывается, UI показывает конфликт. После записи — `rebuildAll(id)`.

**Пересборка компонента.** Удаляются атрибуты, которые плагин писал (`OWN_ATTRS` + прежние `attrs`
формы из `gjsfOwnAttrs`), пишутся новые, части заменяются. Ключ `gjsfKey` (хранится в компоненте) делает
`id` полей уникальными, если форма стоит на странице дважды. Инлайн-стили не используются (иначе
GrapesJS плодил бы правила `#id{}` при каждой пересборке).

**Загрузка проекта / открытие страницы pages.** `refreshStale`: пересобираются компоненты, у которых
`data-gjsf-version` ≠ версии формы, страница (`data-gjsf-page`) другая или форма была помечена удалённой.

**Отправка на сайте.** Скрипт: плейсхолдеры → проверка браузера + «хотя бы один» для обязательных
групп флажков → событие `gjsf:submit` (слушатель может сам отправить через `detail.promise` — так работает
превью редактора) → `fetch(action)` JSON `{data, meta}` (с файлами — multipart + `_meta`) → 2xx: сообщение
/ redirect / сброс; 422: ошибки под полями (коды → тексты из `data-gjsf-codes`).

## grapesjs-pages

Без жёсткой зависимости: читается `editor.PagesManager` и событие `pages-manager:open`. Запись страницы
даёт `{{page.*}}` при сборке и `meta.page_id`. Как и связанные компоненты pages, опубликованные страницы
содержат копию формы на момент публикации (сервер всё равно проверяет по актуальной схеме).

## Открыто

- Локали: en, ru, uk (у остальных плагинов семьи — 23).
- Условная логика (показывать поле, если…), многошаговые формы, капча (кроме honeypot).
- Серверная часть — не в этом пакете: плагин только отправляет на endpoint; приём реализуется в микросервисе по `openapi.yaml`.
- Локальные хранилища (Memory/IndexedDB) не хранят содержимое файлов — только `{ name, size, type }`.
